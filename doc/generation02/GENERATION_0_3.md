# Proposed Generation 0.3 — The Retained Witness

Generation 0.2 separates application storage from key shares and makes local history rewriting observable. Its successful attacks identify the next questions.

1. **Move accepted receipts to several independent observers before relying on silence.** The compromised-witness attack works when custodians never saw the original presence. Retaining pre-release prefixes at two custodians blocks that particular rewrite. Test direct creator-to-observer receipts, lost acknowledgments, observer disagreement, quorum overlap and equivocation evidence. Specify exactly which receipt constitutes authoritative acceptance; do not casually introduce a consensus claim.
2. **Use genuinely separate operators and protected transport.** Remove fault-injection routes from deployment builds; add independently administered hosts, pinned/mutually authenticated transport, per-Capsule enrollment capabilities, key rotation and auditable operational recovery. Demonstrate that application administrators cannot inspect custody storage or distribute a compromised creator client.
3. **Close the real-time authority gap.** Bound sampling-to-commit latency, clock uncertainty, heartbeat obligations and restart handling. Exercise real service process kills, network isolation spanning full schedules, storage stalls, restored witness backups and terminal-state recovery. Distinguish source-clock truth from a local monotonic sanity check.
4. **Decide what custody enforcement can honestly promise.** Static Shamir shares are recoverable by a colluding quorum and irrevocable once issued. Compare an established threshold-decryption protocol that avoids reconstruction with the current construction, while acknowledging that a dishonest threshold may still perform the operation. Obtain specialist review rather than designing a Boolean-policy cryptosystem.
5. **Extend portable interoperability.** Add manifest/checkpoint/custody-response verification in the second language, a broader fixed rejection corpus and property-based event generation with validity-preserving shrinking. The current JavaScript verifier independently covers histories, signatures and semantics, but both implementations still share one written specification and one trusted observation source.
6. **Validate the simple integration boundary.** Keep one-human Solo as the default. A later thin Laravel client should show clear accepted receipts, missed-obligation conditions, disarm status and understandable custody receipts without making users configure key quorums. Keep real disclosure disabled until consent, recovery and delivery safety have been tested.

The next thesis is narrower than “distributed trust”: can a creator obtain an acceptance receipt whose suppression requires compromising enough **independent retained observers**, while ordinary single-authoriser use stays simple? The question follows directly from the successful compromised-witness experiment.
