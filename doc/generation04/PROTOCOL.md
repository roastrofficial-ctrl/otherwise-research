# Four-witness static profile, wire version 4

## Authoritative objects

`Available/proofs.py` specifies restricted canonical JSON, Ed25519 signatures and SHA-256 commitments using the existing Engine primitives. The independently written Node evaluator is `Verifier/available.mjs`; fixed signed examples are `Protocol/vectors/generation04.json`. Canonical JSON permits ASCII, booleans, null, arrays, objects and exact safe integers; duplicate names are rejected on input. Unknown signed-object fields are rejected by proof verification. No Laravel identity or database row enters a signature or policy decision.

The owner signs a manifest containing version 4, Capsule identifier, epoch 1, complete version-1 policy, policy commitment, ciphertext hash, four distinct pinned witness keys, three distinct pinned custody keys, P=3/A=3/f=1, an ordered finite slot list and a single fixed release operation. At most eight contracts and eight slots are permitted in this bounded profile. Contract schemas, authority, version, validity, challenge and expression (`AND`, `OR`, `THRESHOLD`) remain explicit. Each leaf appears once. Attestation contracts use a committed finite observation cutoff.

An evidence message binds version, submission ID, Capsule, **manifest hash**, contract ID and version, challenge, authority, validity interval and boolean assertion. A signature authenticates the entity's statement, not objective truth. An entity appearing in several contracts must sign a different scoped object for each. No proof is transplanted across contracts, challenges, Capsules, policy versions or epochs.

A witness observation additionally binds witness identity, operation identity, sequence/previous receipt, conservative clock interval, proof, interpreted value and closure threshold. `PRESENT` means a timely accepted historical presence claim, not proof of continued biological life. `TRUE`/`FALSE` represent an authority's attestation. Witness sequence links are audit hints; this is not total-order consensus or a global event log.

## State transitions and commit rules

1. **Draft:** trusted creator generates random AES-128-GCM key/nonce, encrypts a synthetic payload with Capsule/policy/epoch AAD, splits the key 2-of-3, and signs the manifest. A recovery kit includes the owner seed, signed manifest, ciphertext, addresses and creator's shares. The creator is allowed to know their own content/key.
2. **Arm:** owner signs `ARM` scoped to manifest and operation. Custodians pin their identity, immutable share and owner-signed enrollment. Each witness commits the manifest and its signed ARM fence. Three distinct ARM fences constitute arming; the client distributes them for retention. An expired first window, changed manifest, closed Capsule or changed custody share cannot be re-armed.
3. **Submit:** an authorised client supplies an authority-signed evidence object. Submission is not acceptance. An honest witness validates identity, scope, interval and value, and commits a first-write lock before returning its signed observation. A duplicate identical submission returns the original signed receipt; changed bytes or contradictory slot proof fail closed. All mutations run through a serial witness server and SQLite FULL transactions.
4. **Accept:** three distinct witnesses must have signed the identical proof for the same slot. The client verifies them and sends **each receipt** directly to witnesses. Each receipt must obtain three signed durable-holder acknowledgements before a new check-in is reported successful. Custody distribution is attempted independently. The CLI fsyncs its updated kit before printing success; the browser verifies signatures and writes localStorage before showing success. Browser storage is not a power-loss durability proof; export the kit independently.
5. **Close:** a witness may sign a FINAL only when its healthy clock's lower bound is at least `deadline + 1 + grace`. It preserves any authentic retained observation for the slot. With none, it signs ABSENT/EMPTY. Final records are immutable; a locally closed slot rejects fresh observations. A peer FINAL alone cannot close an honest node early. Conflicting retained attestation claims close as CONFLICT (a false contract result); they cannot block unrelated satisfied contracts. Multiple presence proofs conservatively retain PRESENT. An exact old receipt remains historically valid after its original submission window closes.
6. **Authorise:** a complete certificate supplies three distinct FINAL records for **every committed slot**, ordered as the manifest. For absence, all three must say ABSENT. For attestation, all three must say TRUE with the same proof. Contract results use one fixed certificate snapshot and `T=max(record.upper)` across that snapshot, including contract and attestation expiration checks. Evaluate the committed expression once at T. The client collapses same-result/same-proof quorum choices to the earliest upper bound, which dominates later choices after every committed contract has started; this prevents exponential repetition of equivalent honest snapshots. No SaaS lookup participates. This finite-batch profile conservatively waits for all slots, including future ones; it does not release immediately on the earliest missed slot of a longer batch.
7. **Enforce/simulate:** each custody provider verifies context, capability requirements, the Python decision and independent Node decision, and checks retained presence/disarm fences before returning a signed share. Two valid provider responses reconstruct only the synthetic message. The operation hash is stable across receipt permutations; certificate hashes may differ. Providers durably remember first release and return the same share for the same operation with a response bound to the presented valid certificate. There is no global exactly-once network delivery claim.

A network error or lost aggregate reply means **uncertain**, not failed evidence and not confirmed success. Retry the same scoped proof; recover original receipts from independent holders. `recover` treats status endpoints as untrusted discovery, deduplicates by signer and verifies all authoritative objects before deriving status. Three retained copies of every receipt allow any three surviving committee members to recover complete successful acknowledgements with at most one faulty member.

## Disarm and amendment

The owner signs DISARM with the same domain and operation binding as ARM. An honest witness signs/commits it only before it has signed its own FINAL. A single authentic retained disarm conservatively fences that node; three distinct DISARM fences establish verified disarm and intersect every possible release quorum in honest members. Disarm does not recall a share already returned or erase a certificate already formed. Once two nodes have closed, a disarm quorum can already be unavailable even if the release certificate is incomplete. The interface explicitly tells the user to disarm before closure starts; this profile does not promise cancellation until the last possible instant.

Armed policy, authorities, committee and schedule cannot be edited. There is no external revocation oracle and no authority-rotation API. For this profile, authority revocation is **owner disarm followed by a fresh Capsule and signed manifest**, with explicit failure if closure has begun. Deleting an authority from a product database has no effect. Epoch is fixed at 1: changing membership/epoch is rejected, not treated as an implicit amendment. The older engine's revocation experiments remain available in earlier profiles.

## Timing and failure assumptions

Honest clock intervals must contain actual UTC; signatures do not establish this. The real Clock checks wall time against monotonic elapsed time with 1-second tolerance/radius and a 30-second maximum observation gap. The service polls the clock while idle. Evidence is accepted only if the entire observation interval lies inside both proof and slot validity; closure requires its lower bound beyond the deadline/grace. Restarts and detected discontinuity require repair. Tests use deterministic clock advancement except the dedicated real-clock tests and TLS system-clock test. A Docker host's clock is not four independent time authorities.

A single authentic retained observation may conservatively block absence even without an accepted aggregate. A failed or late owner check-in exposed to a dishonest observer can therefore deny release for that slot; absence availability is not promised once such an owner-signed proof exists. This does not create a confirmed check-in or satisfy another contract.

Useful liveness assumes three honest witnesses are reachable, healthy, durably writing and receive the same valid request sufficiently before deadline. With interval uncertainty ε and a network/storage round-trip bound Δ, start comfortably before `deadline - 2ε - Δ`; receipt distribution needs an additional bounded phase. Three-second client timeouts are attempt limits, not failure detectors or guarantees of delivery. No finite completion bound is claimed under unbounded delay. A 2+2 partition blocks both quorums; a reachable set of three can progress. An accepted presence can intentionally prevent absence forever for that slot. Byzantine attesters can deny service or lie about facts; a composition that requires their fact may then remain unsatisfied.

Safety requires at most one faulty witness **over the lifetime of the static epoch**, not one at a time while old signing keys accumulate. Honest retained locks must survive or be repaired before signing again. A crashed honest member plus another Byzantine member exceeds the availability budget. Three honest observers can disagree on conflicting authority statements; the affected contract can remain false, while a policy satisfied by other contracts can still authorise release. A low-level cryptographically valid conflicting pair of certificates can be constructed with two equivocating witnesses; the fixed corpus preserves this out-of-budget boundary, and informed custody vetoes retained presence.

## Why intersection is only part of the argument

For any P and A sets of size three out of four, `|P∩A|≥2>f`. At least one intersection signer is honest. Its durable first-write/retained-presence lock prevents signing ABSENT for an accepted presence; its FINAL lock prevents a later new observation from becoming an accepted conflicting quorum. The same intersection argument applies to DISARM versus FINAL, using exclusive durable fences. It fails if honest nodes forget locks, sign before commit, recover from stale checkpoints, use different manifests or trust unbounded clocks. The implementation and tests address those mechanisms separately. This is a scoped certificate safety argument, not a proof of a general BFT consensus protocol.

## Same-identity recovery

A restarted witness marks every enrolled Capsule unrepaired. Restoring its test database also enters repair-required mode. Signing is forbidden in that state. The target supplies a fresh process-local recovery challenge. Three **other** pinned witnesses sign checkpoints binding target key, nonce, manifest, their healthy clock intervals and retained signed records. The owner signs the exact checkpoint hashes and target. The target verifies all records and takes their union with local history, never a majority-voted empty state. No valid lock or fork is deleted. A real-clock target additionally needs overlap with the median peer interval before explicit clock recovery. Successful repair rotates the challenge; replayed old checkpoints/owner commands fail.

This repair requires all three other members. It deliberately trades repair availability for a simple static recovery boundary. Loss of signing identity, committee rotation and custody-node repair are not implemented. A restarted custodian fails closed; the other two can still provide the 2-of-3 operation if healthy. Arbitrary undetected in-process disk corruption, process-memory compromise, cold clones of signing keys and Byzantine storage lying about fsync are not repaired by this mechanism. A restored cold image must follow restart recovery; snapshots of a live process including its nonce/key memory are outside the model.
