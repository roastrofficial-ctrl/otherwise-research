# What the operator can actually do

The final suite passes **16 new methods**. Freshness conformance agrees on **14 fixed signed vectors**, and the unchanged wire-v4 conformance agrees on **66 objects**. The preserved 0.4 suite passes 23 methods and generations 0.1–0.3 pass 54, for **93 passing test methods** across the reruns. Earlier raw artifacts were restored; new regression outputs are kept separately in `doc/results05/`.

The retained ledger contains 20 classified outcomes: 6 prevented, 3 detectable, 4 recoverable, 7 successful. These labels describe different boundaries and must not be collapsed into one security percentage.

The experiment distinguishes prevented actions, detectable lies, recoverable path failures and successful attacks. `doc/results05/attacks.json` is the retained machine-readable classification ledger, generated by tests that execute each case. “Prevented” is conditional on the independently trusted client, independently authenticated provider configuration, witness model and separate custody assumptions in [SECURITY.md](SECURITY.md).

| Operator action | Observed result | Boundary |

| Obtain creator authority by controlling the SaaS account/API | Prevented | No seed, plaintext or aggregate shares are submitted to SaaS |
| Substitute keys, Capsule contents, contracts or destinations | Detectable/rejected | Local commitment, owner signature, ciphertext digest and pinned provider keys |

## Mandatory Hostile SaaS scenario

The integrated driver creates/encrypts/commits/arms locally while the deliberately hostile backend returns false success. The client rejects a relayed false acknowledgement, submits directly and verifies retained presence. It exports only a public projection. The test then stops **Laravel, its hostile backend and PostgreSQL** and verifies they are unreachable.

It deletes the experimental working-device vault and restores an offline encrypted backup created **before the latest accepted check-in**. Fresh independent status recovers that later acknowledgement. The replacement client submits another check-in, disarms and rotates to a fresh Capsule/key. With one real witness process stopped, it accepts/inspects presence through three members; after restart, owner-authorised peer repair restores that witness and fresh inspection verifies retained presence. A separate missed Capsule reaches independent simulated disclosure while SaaS remains stopped. The raw sequence is `hostile-lifecycle.txt`.

Clock advancement is a declared fault-injection convenience, not an ownership capability: all actual owner commands remain creator-signed. Malicious client execution and malicious custody export are separate deliberate successful attacks, never recovery paths. The old device test demonstrates that a valid copied key is genuinely still usable, rather than describing it as revoked by a backup restore.

## Evidence and measurement scope

`tests.txt` contains the new hostile/operator/vault/recovery cases. `conformance.txt` checks 14 fixed signed fresh-status vectors with Python/Node; `conformance04.txt` checks the unchanged 66 existing receipt/release objects. Source pin verification includes a deliberately wrong expected digest rejection. `performance.json` records scrypt/vault, Ed25519, direct check-in/retention, fresh Node-verified status, public/vault sizes and logical provider state bytes. Sample counts and observed maxima are recorded; there is no WAN-tail, independent-organisation or production performance claim.

A signed historical projection is not current authoritative status. The operator can still serve a persuasive fake page, hide ciphertext/metadata or misstate the account view. The trusted client never uses that page as its authority. Plaintext remains fixed synthetic content; there are no real disclosure destinations, SMS or email deliveries. Interactive browser rendering was not audited; real Laravel HTTP integration and the delivered malicious JavaScript execution were exercised.

## Where remaining problems belong

- **Protocol:** static epoch/finite schedule, bounded-clock assumptions, conservative partial-evidence effects, no instantaneous cancellation after closure starts, no in-place authority rotation or committee-wide cold restart. Non-observation is not objective death.
- **Consumer client:** authentic distribution/update roots, device malware, memory/keychain protection, stolen active keys, backup/passphrase loss, cloned-client coordination and clearer recovery ergonomics.
- **Custody implementation:** static-share quorum collusion still decrypts early; no cryptographic conditional enforcement. Hardware/MPC/beacon alternatives require their own assumptions and implementation evidence.
- **Deployment/hosting:** independently administered providers, genuinely independent routes/time sources, retained ciphertext storage, durable hardware, anti-censorship infrastructure and an independent release worker. Moving hosts cannot repair a leaked signing key or change the static-share reconstruction algorithm.

The established result is conditional but executable: controlling this generation's consumer service and public responses alone does not confer the new creator's signing/encryption capability. It can still censor, lie, exploit earlier exposures and induce policy-authorised absence if timely presence never reaches witnesses. Compromising the trusted client or a sufficient custody quorum remains successful.
