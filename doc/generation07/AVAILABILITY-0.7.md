# Availability, ordering and recovery

Safety, completion within a deadline, and eventual recovery are separate claims. Network timeout means an unknown/unavailable response; it does **not** attest a human's absence or a peer's dishonesty.

## Bounded collection

`Missing.collect.gather` uses at most six workers for six holder requests (four for witnesses), validates results independently on the caller thread, excludes invalid sources, records returned invalid payloads/reasons, deduplicates authenticated indices and sorts by configured identity. A response's arrival order cannot supply an extra vote or choose a different domain. The live recipient requires two verified contributions from **each** domain; four arbitrary responses do not suffice.

Holder-to-witness socket timeout is 0.8s and the four-source collection deadline is 1.1s. At least three usable signed snapshots are required. The owner/recipient holder transport uses 4s socket timeouts with a 3s six-source collection deadline; ordinary witness stages use a 2.5s deadline. These are **per-stage local laboratory budgets**, not a global transaction SLA, trusted network synchrony or WAN recommendation. Crypto validation, SQLite commits, repeated receipt-retention rounds and caller scheduling add time. The independent recipient uses a 1.2s fresh-snapshot stage. New Capsule draft uses a usable three-source advisory clock sample and independently installed identity pins, so a missing witness does not force live discovery of all four identities.

HTTP responses are capped at one megabyte before JSON parsing; a per-request absolute timer shuts down the socket, including slow response-body/header reads after connect. The socket timeout and DNS/OS assumptions remain relevant; this is not a hard bound on name resolution or CPU parsing. No blocking context-manager shutdown waits for a hanging worker after the collector deadline. Pending futures are cancelled when possible; already running bounded socket I/O can finish after return. Those worker callbacks only do I/O, not mutate SQLite/accepted state. The caller performs validation and persistence. Bounded workers and request counts are per attempt; global rate/admission control, hard real-time CPU bounds and resource-exhaustion resistance against unlimited callers are **not** implemented. DNS/OS scheduling can also exceed intended socket budgets; production bounds require more than `urlopen(timeout=...)`.

The collector waits for available outcomes until its stage deadline, rather than letting the first two responses select arbitrary metadata. With a sufficient compatible valid quorum within these budgets, one malformed, duplicated, missing or delayed holder per domain does not poison valid responses. Test M exercises malformed success objects, **correctly signed encrypted invalid DLEQ proofs**, oversized payloads, and six-second delayed holders. Test N covers response reordering, a duplicated source payload and explicit deadline completion. A source whose signature/arithmetic fails remains auditable, not a discarded whole quorum. There is no fallback to fewer shares, one domain, unchecked success flags or a different security suite.

## Witness evidence and finality

Witness collection is parallel and requires three of four fresh authenticated responses; it preserves retained observation/disarm vetoes and known per-source prefixes. A named immutable finality certificate replaces v6's requirement that independently sampled record-union hashes match exactly. This avoids harmless head differences from blocking combination, while every holder still checks the signed certificate and current authenticated vetoes. It is **not** a globally atomic evidence read or a new consensus protocol.

Actual `aw4` process stop/restart is exercised: a replacement creator restores an old encrypted vault, discovers later presence from surviving witnesses, submits another check-in, disarms, creates a separate missed-window Capsule and completes release with only three witnesses. Owner-authorised peer repair after restart restores lifecycle state. Finality intersection remains f<=1. An authentic conflicting fork can still cause the conservative union/prefix validator to fail closed; the harness does not prove useful availability for every Byzantine evidence schedule. More than one witness fault, unhealthy clocks or delayed data outside the declared budgets can block release.

The wire4 cancellation limit is retained in V: enough local FINAL fences for an earlier PRESENT window can disable owner disarm before the full release policy is satisfied. This is a successful availability/cancellation attack, not a late-release certificate. A future version must distinguish per-slot closure from final Capsule release commitment and analyse the new intersection/order rules. Changing an old witness's behaviour silently would conceal the experiment.

## Durable evidence without SaaS or latest device

Selected, verified encrypted contributions are stored at a signed three-witness quorum. Fresh three-witness journal reads intersect storage in at least one honest holder under f<=1. Test O restores a creator backup made before those operations, rolls back a custodian DB, and recovers later signed contributions from independently retained journals. A changed reissued response can be compared with the retained original; response randomness alone is not mathematical corruption (the underlying point may be identical). Recipient journal recovery checks inner proof/context/identity before selecting compatible distinct sources.

Journal witnesses attest **storage**, not correctness of encrypted content. No journal replaces release evidence or supplies an administrative approval. The existing wire4 repair checkpoint deliberately excludes new journal fields; restarting with an intact journal preserves it, but restoring a pre-journal backup does not automatically repopulate it. The other three holders can still supply retained operations under the tested one-loss model. Whole-committee journal reconciliation/membership replacement needs a separately versioned protocol.

| Disaster | Confidentiality | Eventual authorised disclosure / recovery |
|---|---|---|
| One lost custodian and one lost authorisation holder | Missing-domain requirement preserved if remaining secrets uncompromised | Surviving two in each domain suffice; no need to reconstruct reusable private keys |
| Two lost holders in either domain | Fail closed; missing capability remains missing | Blocked without an independently secured backup or prior valid retained partials; inaccessible content is not a useful service |
| Entire domain compromised | Other independent domain remains indispensable under secure setup/honesty assumptions | Compromised domain can censor indefinitely; confidentiality is not availability |
| Whole committee replacement / infrastructure migration | New distinct Capsule/key epochs protect new ciphertext; historical exposure survives | No reviewed in-place resharing/refresh/replacement is implemented. Requires old quorum plus authorised re-encryption, secure migration/backup, or a future reviewed protocol; no hidden all-key coordinator |
| SaaS shutdown or DB rollback | No content/creator keys or authoritative protocol state depend on it | New deployment has no SaaS; prior full Laravel/database disappearance/rollback experiments are rerun. Independent clients use protocol endpoints |
| Creator device loss / old vault | Local capability encrypted; passphrase and backup still necessary | Fresh independent witness/journal state supersedes stale cache. No capability backup/passphrase means no owner/recipient reset |
| Witness restart | Old records/keys stay bound; quarantine before signing | Existing authenticated three-peer repair; journal transfer limitation stated above |
| Cold witness-committee restart / partial restoration | Confidentiality fails closed while quorum/anchors are unavailable | Existing witness repair needs owner-signed authority and three ready peer checkpoints. A departed creator cannot supply a new repair signature, and an entirely quarantined committee cannot bootstrap itself from three ready peers. No cold-start/admin bypass is implemented; one-loss survival is not decades-long autonomous recovery |
| Custodian/authorisation-holder restart | Own share and immutable context persist | Actual process exits before/after commit tested; fresh witness reads required before retry, durable cached response survives postcommit death |
| Temporary partition / two missing witnesses | No fabricated quorum or timer-based release | Stalls; resume/retry after enough healthy peers and repair. No wall-clock timestamp supplies missing ordering |
| All keys/anchors restored from compromised global backup | No guarantee | Shared administrator can steal both domains and rewrite history; no universal detection/recovery |

Backups, common deployment credentials, shared cloud administrators, a compromised CA or signed update channel can collapse nominal committees into one effective compromise domain. The Docker laboratory deliberately demonstrates that collapse in K. It does not deploy independent organisations.
