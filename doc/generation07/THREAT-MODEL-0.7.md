# Threat model — two indispensable capability domains

This is a synthetic research harness, not a production encryption service or a cryptographic audit. Separate containers, keys and volumes establish cryptographic role separation in the experiment; **one Docker host administrator still controls all roles**. The correlated-compromise attack succeeds.

## Conditional guarantee

Given secure independent creation, an uncompromised creator/recipient boundary, authenticated pinned commitments, sound AEAD/HKDF/Ed25519/DH/DLEQ assumptions, and no previously released missing-domain threshold for this Capsule, extracting **every custody-local secret** does not provide the other domain's content-key component. Before legitimate finality, honest authorisation holders refuse to produce that component's decryption capability. The symmetric statement applies to full authorisation-domain compromise and honest indispensable custody capability.

At least two holders are required **in each domain**. For a malicious full domain, the other domain must have fewer than two extracted/colluding shares and enough honest holders following the stated gate; witnesses remain within the preserved f<=1 model. “An uncompromised authorisation capability” means sufficient capability remains unavailable, not merely one honest holder when the other two collude. Availability additionally requires the response and storage assumptions in AVAILABILITY-0.7.md. The integrated reference composition is unreviewed: the algebra/primitive assumptions explain the claim; finite attack tests do not constitute a security proof.

A confidentiality failure includes obtaining the content AES key, both XOR components, equivalent usable partials/wrapping secrets, authenticated plaintext, or delivery to a substituted recipient. Reconstructing a reusable scalar is **not** required. A and B tests obtain one real component, bypass all APIs and attempt the missing unwrap/AEAD operation. C obtains both and successfully decrypts before a valid decision.

A signature authenticates a speaker. DLEQ authenticates arithmetic relative to a committed public share. Neither proves the stated real-world fact or legitimises a release by itself. Absence remains missing authoritative timely evidence, not objective death or consent.

## Exposure and lifecycle limits

Neither provider reconstructs a reusable scalar during honest release. Each computes one point; the recipient reconstructs two **per-Capsule components**, then the per-Capsule AES key. No SaaS/online untrusted coordinator receives both components. The trusted creator necessarily had the plaintext and setup secrets; this is not DKG. Backups of shares or creation memory can defeat the independence assumption. The random plaintext-commitment salt is encrypted with the content so a public commitment alone does not provide a simple dictionary test for short messages.

Disarm constrains honest holders before wire4 finality; it cannot delete already learned secrets, invalidate a copied ciphertext against old combined secrets, or stop combined-domain collusion. A first durable local FINAL/DISARM, not wall-clock arrival, is the ordering fact. Three-signature conflicting certificates intersect honestly under f<=1. See PROTOCOL-0.7.md for finality and unchanged expiry semantics.

No in-place share refresh, DKG, safe full committee replacement, HSM boundary, secure deletion, post-quantum security or decades-long operating guarantee is implemented. New Capsule/key epochs protect **new ciphertext**; old exposure survives. A mandatory creator-held secret would prevent autonomous release when the creator disappears; this harness instead trusts independently indispensable committees.
